## Contradictions

1. **1×1 CFU cycle count.** Current log: **828,991,457**. Earlier reference
   (`proj/mnv2_cfu_package/README_MNV2_EXISTING_CFU.md`, Renode/Verilator):
   448,959,843. Team-quoted value: 448,945,811. These differ by ~1.85×, so
   they come from different platforms/setups. The old CPU-only figure
   (1,216,038,298 / 1,216,227,740) belongs to the old setup and **must not**
   be combined with the current logs. The old 2.708× / 63.08 % are
   historical.
2. **Previously quoted "current combined" resources** (top LUT 6192 / FF
   4504; CFU LUT 1514 / FF 1081) match a **1×1-only** CFU (current 1×1
   report: 6,187 / 4,504; CFU 1,511 / 1,081; CFU FF 1,081 = no 3×3 unit), not
   a combined 1×1+3×3 design. The quoted WNS +0.243 ns appears in no report
   (current: +0.962 / +0.372 / +0.322 ns). Treat all as historical.
3. **Untouched operators vary between runs.** MEAN: 12,170 → 12,019 →
   **21,806** ticks (+81 % in D, ≈ +10.0 M cycles), with no code change to
   MEAN. The D − C total difference is −42.1 M cycles, so this variation is
   ~24 % of the measured sliding-window gain. Single runs cannot separate
   effect from noise.
4. **Stride-2 depthwise layers are slower in D than in C** (+22.0 %, +4.5 %,
   +26.8 %, +0.5 % for events 6, 14, 26, 53), although stride-2 layers do
   not use SHIFT_RIGHT and should run the same code path. Events 60 and 64
   (stride 1) are also slower (+10.7 %, +1.7 %). Unexplained. It may be
   run-to-run variation or a C/D build difference (e.g. C built from
   `42c42a5` with a 1-cycle RUN vs D's 3-stage RUN).
5. **Banner in runtime logs** says `Mode: EXISTING MNV2 CFU / eligible 1x1
   CONV_2D` for C and D too. It is not a valid configuration indicator.
6. **Rounding**: LOAD reduction is 71.265 %: 71.27 % rounded, 71.26 %
   truncated. Previous documents used 71.26 %.
7. **Figure 4 spec**: the requested window lettering (`B C D / E F G /
   H I J`) contradicts the row-wise shift in `Depthwise3x3Mac`; corrected in
   `figures/diagrams/sliding_window_diagram_spec.md`.
8. Utilization stage mismatch inside the earlier `EXPERIMENTAL_RESULTS.md`:
   values were unlabeled. Now labelled post-place.

## Ready for Paper

Usable now, with the stated caveats:

- **Table: CFU-configuration progression (B → C → D)**: cycles, speedup vs
  1×1 CFU (1.347×, 1.446×), post-place CFU LUT/FF/BRAM/DSP, post-route
  WNS/TNS at 75 MHz. Caveat: single runs; platform to be stated.
- **Fig. `end_to_end_performance.pdf`**: B/C/D cycles by operator class.
  Needs regeneration once CPU-only exists.
- **Fig. `sliding_window_instructions.pdf`**: label the counts "per
  inference, derived from kernel loop structure" until a counter log exists.
- **Fig. `fpga_resources.pdf`**: CFU LUT/FF, post-place.
- Resource deltas: 3×3 unit +167 LUT / +394 FF / 0 DSP / 0 BRAM (CFU level);
  sliding window +1,015 LUT / +182 FF.

**Not ready:** any speedup vs CPU, any claim about run-to-run stability,
per-layer sliding-window gains, 400/400 equivalence as reproducible
evidence, power.

**Overall: NOT READY.** The CPU-only baseline, the end-to-end anchor of the
paper's story, is missing, and the runtime logs lack platform/commit
metadata.
